# Стриминг серверного рендеринга

Стриминг позволяет отправлять HTML порциями по мере готовности, вместо ожидания полного рендеринга всей страницы.

## Как это работает

Вместо того чтобы ждать все асинхронные компоненты, сервер отправляет:

1. **Сначала** — HTML оболочки и скелетоны (Suspense fallback)
2. **По мере готовности** — содержимое каждого фрагмента

В браузере React вставляет готовые фрагменты в нужные места без полной перезагрузки.

## Suspense как точка стриминга

```tsx
import { Suspense } from 'react';

function Page() {
  return (
    <div>
      <h1>Мой блог</h1>
      <Suspense fallback={<p>Загрузка постов...</p>}>
        <PostsList />
      </Suspense>
      <Suspense fallback={<p>Загрузка рекомендаций...</p>}>
        <Recommendations />
      </Suspense>
    </div>
  );
}
```

В этом примере:

- `<h1>` отправится сразу
- `<PostsList>` и `<Recommendations>` стримятся независимо
- Пользователь видит заголовок, пока остальное загружается

## Порядок стриминга

1. **Синхронный HTML** — корневой layout и статический контент
2. **Suspense границы** — по мере завершения каждого асинхронного компонента
3. **Inline скрипты** — React обновляет DOM через inline `<script>` в стриме

## Когда использовать стриминг

- Тяжёлые дашборды с независимыми виджетами
- Страницы с множеством асинхронных запросов разной длительности
- Контент, где часть данных приходит быстро, а часть — медленно
- Улучшение Core Web Vitals (LCP, FCP)
